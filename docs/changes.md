## 3 编码与构建

- 原方案：全部文件按 UTF-8 直接 javac；Git 自动 CRLF 转换开启。
- 问题：原教师源码同时含 GBK 与 UTF-8，原字节恢复后统一 UTF-8 读入会失败；Git 也可能改变原件换行字节。
- 修改：tools/compile.ps1 对显式列出的源码先严格解码 UTF-8，失败则用 GBK，只在忽略的 build 目录写 UTF-8 编译副本；使用 `javac --release 19`；`.gitattributes` 对 src/resources 禁用文本转换。
- 优点：源文件哈希保留，支持现有 Java19，无需改教师原件。
- 缺点/代价：编译多一步副本生成，IDE 需要正确识别各文件编码；PowerShell 构建目标是 Windows。
- 验证/回退：新目录独立编译、教师哈希清单和 staged blob 字节检查；旧编译入口已保存在本地快照。

## 4 复现验收与脚本缺陷

- 原方案：RunHard 只看父 JVM 退出码，提醒用户手工查看 CSV。
- 问题：Stage3 父 JVM 在记录 TIMEOUT/OOM/FAIL 后也可能正常退出，造成假阳性。
- 修改：新增 BenchmarkAcceptance，拒绝非 SOLVED、错误题目/初态/目标/指标/步数和实际父端超预算；解析真实 TSV 并回放；reproduce.ps1 调用验收并保存环境、输入及源码哈希；支持来源明确的热缓存对照。
- 优点：无需用户猜测是否成功，失败状态自动非零。
- 缺点/代价：新增独立验收过程；父 JVM 自身首次启动未单独量测，不能把父端与搜索差值称为纯启动时间。
- 实际失败：第一次迁移后 cold 搜索成功，但 PowerShell 将 java -version 的正常 stderr 当异常，入口返回 1。改用重定向的 Process 获取版本后，完整入口返回 0；失败日志和首次成功搜索都保留。
- 验证/回退：BenchmarkAcceptanceTest 拒绝 TIMEOUT/OOM/FAIL/UNSOLVABLE；完整 RunHard/RunWarm 实跑，原日志不覆盖。
